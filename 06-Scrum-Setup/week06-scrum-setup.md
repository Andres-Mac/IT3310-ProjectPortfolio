## Agile Delivery Fit
The parts that will benefit from the iterative delivery are the patients’ intake forms, and the scheduling workflows across the six clinics. By breaking down the project intake and scheduling system need into smaller pieces, and by creating a sprint goal the scrum team will gain increments for the project. The need for feedback is necessary as the iterative approach indicates that delivering the work into small pieces, Novatech will identify how staff will react and adapt to the new systems intended to be changed. It also creates a conversation among stakeholders and provides a new implementation approach as they move along with new systems. During the process of learning and adaptation, the staff can get trained and learn from the newly implemented software. As the sprint goal moves along, one project area that may still require strong advance would be transferring data into the new system. However, this should be planned ahead of time with stakeholders.

## Sprint Planning Reflection
The backlog items I chose will help the team organize and start off this sprint goal effectively. Our sprint goal is to Create a Scheduling intake form prototype for all six clinics. For the team to start the sprint goal, the scrum team will create a rhythm of delivery and be accountable for each event within the process. The team will first define the standard intake fields that all six clinics use to create a scheduling workflow prototype and communication on update for RCHN stakeholders within the project. The item I intentionally deferred was the Clinic Staff Training Outline because the team is currently on plan one of the sprint goals and I preferred the RCHN team to focus on the core problem of the intake and scheduling system across all six clinics before training on how to use the newly implemented systems. I do plan to create a training outline for the RCHN staff on how to properly use the new systems, but for now this backlog should be used later for a different sprint goal.
